THE 70/30 RULE: WHY AI NEEDS AN EXPERIENCED PILOT

AI handles 70% of the typing. Experience handles 100% of the decisions. That distinction changes everything.

There's a seductive narrative in tech right now: AI has democratized software development. Anyone can build an app. Describe what you want, the machine produces code. No experience necessary.

I've spent the last year testing this by building production Rails applications with AI assistance. Real software, real customers, real infrastructure. And I've found that the narrative is half right—which makes it dangerous.

AI genuinely transforms what's possible. I've delivered complete business applications in weeks that would have taken a traditional team months. But the productivity gain doesn't come from AI replacing judgment. It comes from AI amplifying judgment. That distinction changes everything.

The no-code movement promised something similar a few years ago. Drag and drop your way to a business. For certain use cases, these tools deliver real value—forms, simple CRMs, basic inventory tracking. They've gotten genuinely good at that layer.

But then you need multi-tenancy, where each customer's data must be perfectly isolated. You need background jobs that don't block requests. You need queries that don't collapse at fifty thousand records. You need proper authorization that doesn't leak data between users.

This is where no-code hits a wall. Not because the tools are bad, but because the problems require judgment that no visual interface can encode. AI-assisted coding faces the same wall, just higher up. It generates vastly more sophisticated code. It understands frameworks, patterns, best practices. But it still can't make the judgment calls that determine whether software actually works in production.

Consider authentication. Ask AI to build it and you'll get something that works. Accounts, passwords, sessions. The code follows patterns correctly.

But will it handle the edge case where email delivery takes thirty seconds and blocks the request? Will it scope queries to the current tenant, or fetch users by ID directly—leaking data between customers? Will it use the hashing algorithm recommended today, or the one that was popular when the training data was collected?

These aren't exotic concerns. They're the ordinary problems that separate software that works from software that survives production.

I frame it as the 70/30 rule. AI handles about 70% of what I type—controller scaffolding, migrations, templates, tests, CSS. Patterns so well-represented in training data that AI produces them nearly perfectly.

But humans handle 100% of the decisions. Architecture: monolith or services, which database, how to structure the data? Security: is this query scoped correctly, is this input sanitized? Business logic: does this workflow actually match what the client needs, what happens in this edge case?

The 70% isn't 70% of the value. It's 70% of the typing. Value lives in the decisions.

There's an analogy I keep returning to. AI can generate architectural blueprints. Describe what you want—three bedrooms, open floor plan, modern kitchen—and you get professional-looking plans.

But no one hands those plans to someone off the street expecting a livable house. You still need builders who know the blueprints don't show where walls need extra support. Who recognize the plumbing will cause pressure problems. Who understand local building codes.

Software works the same way. AI compresses mechanical coding into minutes instead of hours. That compression is real and valuable. But it's a starting point for skilled execution, not a substitute for skill.

What does this mean if you're trying to get software built?

The hype says anyone can build an app now. Technically true, practically useless. Anyone can generate code that looks like an app. Generating code that handles edge cases, scales under load, keeps data secure, and stays maintainable—that requires judgment AI doesn't have.

The realistic picture: experienced developers with AI assistance now deliver what used to require teams. A project that needed €80,000 over four months might now need €20,000 over four weeks. That's a genuine transformation in what's economically viable.

But the experienced developer part isn't optional. The same tools that make a senior developer dramatically more productive can lead an inexperienced team into security holes and architectural dead ends. AI assistance only works because someone with judgment is at the controls.

Programming skill isn't knowing what code should look like. It's intuition built through years of writing, debugging, and living with consequences. That intuition tells you something's wrong before you can articulate why. It makes you pause at an authorization check that passes tests but doesn't feel right. AI can't have that intuition—it has patterns, not judgment.

The winning formula right now is clear: experienced developers using AI to eliminate mechanical work, focusing entirely on the decisions that determine success. That's the 70/30 rule. AI handles the typing. Experience handles everything else.
